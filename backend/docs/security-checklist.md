# Security Checklist (M1, used from Week 3, reviewed in Week 8)

Use part A as **coding rules from day one**. Fixing these in week 8 costs far more than writing them correctly in week 3. Part B is what M1 + M2 + M5 verify in week 8.

PR reviewers: tick the relevant rows in the PR description.

## A. Coding rules (every PR)

### Authentication and tokens (M2)
- [ ] Passwords hashed with **argon2id**; plain password never logged, never returned.
- [ ] Password rules come from `password-policy.ts` (FE and BE use the same regex).
- [ ] JWT: algorithm pinned on verify (e.g. `algorithms: ['HS256']`), `exp` = 15 min, secret read from Secret Manager / env, never hard-coded.
- [ ] Refresh tokens: only the SHA-256 hash is stored; reuse of a revoked token revokes the whole `familyId`.
- [ ] Login error is the same for "unknown user" and "wrong password" (no username enumeration).

### Authorization (M2, M3, M6)
- [ ] Every controller is protected by default (`JwtAuthGuard` global); public routes use an explicit `@Public()`.
- [ ] Every route with a course resource calls `AccessPolicy` ([rbac-matrix.md](rbac-matrix.md)). Role check alone is not enough.
- [ ] Queries for personal data are scoped by the caller: `where: { id, userId: user.id }`. Never load by id and compare later (IDOR).
- [ ] Responses never include `passwordHash`, `accessPasswordHash`, `tokenHash`, storage keys, or `correctOptionIndex` for students. Use response DTOs, not raw Prisma objects.

### Input validation (all backend)
- [ ] Global `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })`. Blocks mass assignment such as `{"accountType":"Admin"}` on `PATCH /users/me`.
- [ ] Every DTO field has a type and bounds (`@MaxLength`, `@Min/@Max`, `@IsIn` for enums).
- [ ] Pagination: `pageSize` capped (e.g. ≤ 100).
- [ ] IDs from URLs parsed as integers (prefix `crs_` stripped in one shared pipe).

### Database (M2, M3)
- [ ] Prisma query API only. **`$queryRawUnsafe` / `$executeRawUnsafe` are forbidden.** `$queryRaw` with a tagged template is allowed only with a reviewer's OK.
- [ ] Multi-step writes in `prisma.$transaction`; no network calls inside a transaction.
- [ ] Migrations reviewed like code; no `prisma db push` against shared databases.

### Files (M2, M6)
- [ ] Size and type checked **before** signing and **again** at `/complete` ([storage-cdn-iam.md](storage-cdn-iam.md)).
- [ ] Keys generated by the server; user file names never used in keys.
- [ ] Submissions downloaded with `Content-Disposition: attachment`.
- [ ] Buckets private; no `allUsers` on media/submissions.

### HTTP layer (M2, M5)
- [ ] `helmet()` enabled.
- [ ] CORS: exact origin allowlist from config (`https://<frontend-domain>`, `http://localhost:5173`); no `*`.
- [ ] Global exception filter returns `{ error: { code, message, requestId } }` only; no stack traces in production.
- [ ] Rate limits: login, register, refresh, AI tutor (per user). Edge rate limit in Cloud Armor.

### Logging (all)
- [ ] Structured JSON logs with `requestId`, `userId`, route, status, latency.
- [ ] Never log: passwords, tokens, `Authorization` header, signed URLs, full request bodies of auth routes.

### Secrets (all)
- [ ] No secret in the repo. `.env` is git-ignored; only `.env.example` with fake values is committed.
- [ ] Production secrets live in **Secret Manager**, injected into Cloud Run as env vars or mounted secrets.
- [ ] If a secret is ever pushed: rotate it first, then clean history. Deleting the file is not enough.

### Frontend (M4)
- [ ] Access token kept in memory; refresh token storage agreed with M1 (trade-off in ADR-008).
- [ ] No `dangerouslySetInnerHTML` on user content (course descriptions, feedback, AI answers).
- [ ] `VITE_*` variables are public by design; never put secrets in them.

### AI tutor (M6)
- [ ] Retrieval always filters by `courseId` **and** checks `canViewContent` first.
- [ ] Retrieved text is passed as data inside the prompt, not as instructions; the system prompt says to answer only from the provided passages and refuse otherwise.
- [ ] Per-user rate limit and max tokens per answer (cost control).
