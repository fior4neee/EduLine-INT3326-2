# Non-functional requirements: current status

Status: ✅ done · 🟡 partly done · ❌ not started. Paths are relative to `backend/src/` unless they start with `backend/`, `frontend/` or `infrastructure/`.

| NFR | What the platform needs | What the code does now | Where | Status |
|---|---|---|---|---|
| **Security: authentication** | Secure login and sessions | JWT access token (15 min) in the `Authorization` header. Refresh tokens rotate on every use and are stored as SHA-256 hashes; reusing an old one revokes the whole session. | `common/auth/`, `modules/auth/token.service.ts` | ✅ |
| **Security: password storage** | Passwords can't be recovered if the database leaks | argon2id with OWASP settings. A failed login takes the same time whether or not the username exists, so usernames can't be discovered by timing. | `common/security/hashing.ts` | ✅ |
| **Security: password policy** | Strong passwords | 8–32 characters with an uppercase letter, a number and a special character. Checked on both backend and frontend. | `modules/auth/password-policy.ts`, `frontend/src/lib/password-policy.ts` | ✅ |
| **Security: authorization** | Students see only their own data and the courses they're enrolled in; instructors manage only their own courses | Login and role guards on every route, plus per-course checks (staff, enrolled, preview lessons). Verified on Cloud Run: 401 / 403 / 200. | `common/guards/`, `modules/access/access-policy.service.ts` | ✅ |
| **Security: input validation** | Reject bad or unexpected input | A global validation pipe validates every request body and rejects unknown fields. | `app.module.ts` | ✅ |
| **Security: abuse protection** | Protection against brute force and spam | Rate limits per user (per IP when logged out): 120/min overall, 10/min on login and enrollment. **Gap:** counters live in each instance's memory, so with several Cloud Run instances each one counts separately. | `common/guards/user-throttler.guard.ts` | 🟡 |
| **Security: HTTP hardening** | Safe browser and API behaviour | Helmet with a content security policy, CORS limited to listed origins, `x-powered-by` removed. | `main.ts` | ✅ |
| **Security: secrets and infrastructure** | No secrets in code; database not exposed to the internet | Environment variables validated at startup. No secrets in the Docker image; the container runs as a non-root user. Cloud SQL is reachable only through the Auth Proxy (port 5432 closed). | `common/config/env.validation.ts`, `backend/Dockerfile`, ADR-009 | ✅ |
| **Privacy** | Don't leak personal data | Logs record the route pattern, not the full URL, so IDs and tokens stay out of logs. A missing or hidden lesson both return 404. Analytics are staff-only. | `common/logging/request-context.middleware.ts`, `modules/progress/progress.service.ts` | ✅ |
| **Scalability** | Handle peaks, such as many students taking a quiz at once | The API is stateless, so Cloud Run can add instances. Database connections are capped at 10 per instance. | `backend/Dockerfile`, `DATABASE_URL` | ✅ |
| **Performance: queries** | Pages stay fast as data grows | 29 indexes and unique constraints. Lists are paged (max 100 per page). Progress for all of a user's courses takes 2 queries, not one per course. | `backend/prisma/schema.prisma`, `common/pagination/pagination.ts`, `modules/progress/course-progress.service.ts` | ✅ |
| **Performance: caching** | Catalog and course outlines are read far more often than they change | No Redis or cache layer yet. | n/a | ❌ |
| **Media delivery** | Large videos and files served through a CDN, not through the API | Videos are stored as keys, but URL signing is still a `TODO(M6)` and lessons fall back to a sample video. No CDN. Upload limits (200 MB / 100 MB) are defined but not enforced anywhere. | `modules/content/content.service.ts:82` | ❌ |
| **Concurrency: quiz peak** | Many simultaneous submissions are each graded correctly, exactly once | The database allows at most one in-progress attempt per student per quiz, and scoring is implemented and tested. **Gap:** no endpoint to start or submit an attempt. | integration-review #21 | 🟡 |
| **Consistency** | Progress, grades and enrollments stay correct under concurrent requests | Changes run in transactions. Progress percent only goes up, even when two heartbeats arrive together. Completing a lesson or course is safe to repeat. | `modules/progress/progress.service.ts`, `modules/enrollments/enrollments.service.ts` | ✅ |
| **Reliability: events and notifications** | Notifications are never lost or sent twice | Events are written in the same transaction as the change that caused them (outbox). A processor claims them safely across instances and retries failures up to a limit; the database blocks duplicate notifications. **Gap:** events are processed inside the API instead of going through Pub/Sub (the topic and dead-letter queue already exist on GCP). | `events/outbox-processor.service.ts` | 🟡 |
| **Data retention** | Students' results are never lost | Deleting a course archives it and keeps all results. Foreign keys and unique constraints throughout the schema. | `backend/prisma/schema.prisma` | ✅ |
| **Availability** | Restarts and deploys don't break requests | `/health` queries the database and is used by Cloud Run. The server shuts down cleanly when stopped. | `modules/health/health.controller.ts`, `main.ts` | ✅ |
| **Observability** | Production problems can be traced and debugged | Every request gets an ID (returned as `X-Request-Id`), one JSON log line with latency for Cloud Logging, and one error format with stable codes. **Gap:** no dashboards, alerts or tracing. | `common/logging/request-context.middleware.ts`, `common/errors/all-exceptions.filter.ts` | 🟡 |
| **Maintainability** | A 6-person team can work in parallel | Separate modules that only write their own tables. Swagger at `/api/docs`. Plan and design docs per member. | `modules/`, `backend/docs/` | ✅ |
| **Testability and quality** | Changes don't break existing features | 75 integration tests, unit tests and evals on VMLU data. The frontend type-check passes on `develop`. **Gap:** no CI, so nothing runs these checks before a merge (integration-review #20). | `backend/test/` | 🟡 |
| **Deployability** | Reproducible builds and deploys | Multi-stage API Dockerfile, local Postgres with docker-compose, API deployed to Cloud Run. **Gap:** fresh installs need a manual `prisma generate` (#23), and the frontend has no Dockerfile or deploy. | `backend/Dockerfile`, `infrastructure/` | 🟡 |
| **Usability and localization** | Vietnamese learners on any device | Vietnamese UI. Tailwind responsive breakpoints in 17 frontend files. | `frontend/src/` | ✅ |
| **Accessibility** | Usable with a screen reader and keyboard | Some `aria-*` and `alt` attributes (46 uses), but no audit. | `frontend/src/` | 🟡 |
| **Load testing** | Evidence the platform holds up at 50 / 100 / 500 users | No k6 scripts yet (planned for week 9). | n/a | ❌ |
